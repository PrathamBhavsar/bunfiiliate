1. System Architecture & Ingestion Pipeline

SEC-01

Requests are ingested without synchronous database calls. Hot-path lookups read from an in-memory Snapshot (in ArcSwap) refreshed via PostgreSQL LISTEN bf_config. Events write directly to a segmented Write-Ahead Log (WAL) with group-commit fsync, then flush asynchronously into PostgreSQL.

Schematic: Ingestion Hot Path → Storage → Outbox Processing

2. Technical Capabilities & Specifications

SEC-02
Ingestion & Hot-Path Pipeline
  • Zero-DB validation: In-memory snapshot in ArcSwap, dynamically refreshed on Postgres LISTEN bf_config.
  • Durable WAL spool: bf-spool segmented write-ahead log with [len u32|crc32|json] framing and group-commit fsync.
  • Batched database ingest: Flushes acked batches over a bounded MPSC channel using INSERT ... SELECT UNNEST(...) ON CONFLICT DO NOTHING.
  • Load shedding: Bounded memory channels return HTTP 503 backpressure rather than unbounded memory allocation.
  • Compact client script: tracker.min.js (<2 KB) handles first-party cookies (bf_vid, bf_ref) and beacon payloads.
  • Webhook verification: Constant-time HMAC-SHA256 signature verification for Stripe (t=,v1=), Paddle (ts=;h1=), and generic events.
Financial Ledger & Accounting
  • Pure domain core: bf-core contains all financial rules, currency types, and state machines without I/O dependencies.
  • Double-entry bookkeeping: Four accounts (Expense, AffPending, AffPayable, Cash).
  • Append-only immutability: Postgres triggers forbid UPDATE and DELETE operations on ledger_entries.
  • Balanced by construction: LedgerTxn requires debits equal credits per currency. Deferrable constraint triggers verify sum(amount_cents) = 0.
  • Integer cents: All money is stored in integer minor units (cents: i64). Floats are strictly prohibited.
  • Basis-point math: Exact commission calculation in basis points (1 bps = 0.01%) using round-half-up math in i128.
Multi-Tenancy & Security
  • Workspace scoping: Strict multi-tenant isolation across Workspaces, Programs, Affiliates, and Referral Codes.
  • Role-based access: Scoped authorization for super_admin, admin, and affiliate.
  • HttpOnly cookie sessions: Short-lived 15-minute JWT access cookies (bf_at) with SameSite=Strict.
  • Rotating refresh tokens: Opaque 30-day tokens (bf_rt) stored as SHA-256 hashes; reuse immediately revokes the family.
  • CSRF prevention: Strict origin validation on all state-mutating HTTP requests.
  • Argon2 password hashing: Robust password derivation for all stored user credentials.
Operations & Background Processing
  • Single-image deployment: Compiles to two binaries (tracker and api); worker is embedded via api serve --with-worker.
  • Concurrency control: Inbound events and outbox messages claimed via FOR UPDATE SKIP LOCKED.
  • Advisory locks: Periodic auto-approve and rollup ticks coordinated via pg_try_advisory_lock.
  • Transactional outbox: Outbound webhooks dispatched with exponential backoff and retry counters; emails sent via Lettre.
  • Attribution engines: Configurable first-touch and last-touch attribution models.
  • Traffic hygiene & fraud rules: In-memory sliding-window IP velocity limiting, Woothee bot filtering, and click deduplication.

4. Double-Entry Ledger Posting Matrix

SEC-04

All financial movements post to immutable ledger rows. The sum of signed postings in every LedgerTxn strictly equals zero by construction and database verification.

Lifecycle Trigger Event Debit Account (+) Credit Account (−) Financial Meaning
Conversion Created Expense AffPending Commission liability created; held pending verification window
Hold Approval AffPending AffPayable Hold period expires; commission balance is eligible for payout
Pre-Approval Rejection AffPending Expense Conversion rejected or refunded prior to approval; cancels liability
Post-Approval Chargeback AffPayable Expense Approved commission reversed (payable balance may become negative)
Payout Batch Paid AffPayable Cash Funds disbursed to affiliate; liability cleared against merchant cash

5. Quickstart Runbook

SEC-05

Prerequisites: Rust 1.80+ (via rustup), PostgreSQL 16 on port 5433, and Node.js 20+.

# 1. Configure toolchain environment
export PATH=/opt/homebrew/opt/rustup/bin:$HOME/.cargo/bin:$PATH
export DATABASE_URL=postgres://pratham@localhost:5433/postgres

# 2. Start PostgreSQL 16 cluster
/opt/homebrew/opt/postgresql@16/bin/pg_ctl -D ~/.bunfiiliate/pg16 -o "-p 5433 -k /tmp" start

# 3. Execute test suite & lint checks
make ci

# 4. Bootstrap initial workspace and super admin user
cargo run -p api -- bootstrap \
  --email admin@example.com \
  --password "SuperSecretPassword123!" \
  --workspace "Acme Corp"

# 5. Start API server with embedded background worker (port 8080)
cargo run -p api -- serve --with-worker

# 6. Start hot-path tracker daemon (port 8081)
cargo run -p tracker

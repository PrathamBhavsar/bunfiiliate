# 0004 Postgres RLS

**Decision**: do not enable RLS. Keep app-layer scoping (`ws: Uuid` in every tenant db fn, ADR/anti-pattern 31) enforced by the C02 matrix and `make sql-lint`. RLS stays an opt-in hardening path.

**Spike** (not applied): `crates/db/migrations/0060_rls_spike.sql.disabled`, tests `crates/db/tests/rls_spike.rs` (`#[ignore]`, `cargo test -p bf-db --test rls_spike -- --ignored`, PG16 passes). It puts a policy `workspace_id = nullif(current_setting('app.ws', true), '')::uuid` on `programs` and a non-owner role `bf_app`.

**What the spike showed**
- `rls_blocks_cross_ws_select_without_app_filter`: a query with no workspace predicate returns only the session workspace; a cross-workspace INSERT fails `WITH CHECK`; unset `app.ws` returns zero rows (fail closed).
- `rls_set_local_resets_after_commit`: `SET LOCAL ROLE` and `set_config(.., true)` vanish at commit, so a pooled connection does not leak a workspace. This only holds inside a transaction: a bare `SET` leaks across pool users.
- `rls_owner_role_bypass_documented`: the owner sees every row (no `FORCE`). Migrations, the tracker and the worker connect as owner (they span workspaces), so they are unprotected. RLS therefore covers only the api request path.

**Why not default**
- Every api request would need its own transaction with two extra statements, including reads that are single queries today.
- Needs a second db role and `DATABASE_URL` split, which complicates self-hosting (compose, systemd, backup/restore).
- `clicks` has no `workspace_id` column (it joins through `programs`), and the partitioned table plus `ledger_entries` (no `workspace_id` either) would need a column or a join-based policy; the join policy cost on `ledger_entries` was not measured here and is the main unknown.
- Super admin needs a bypass path (a second policy or role).
- App-layer scoping is already machine-checked and the matrix found no leaks (`docs/audit/findings.md`).

**Revisit if** a leak is found that the matrix and lint miss, or a hosted multi-tenant offering needs defense in depth. Then: add `workspace_id` to `clicks`/`ledger_entries`, measure, and ship as a numbered migration behind an opt-in role split.
